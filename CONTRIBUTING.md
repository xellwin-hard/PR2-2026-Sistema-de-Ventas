# Guía de contribución

Este repositorio pertenece al equipo académico NexCode y se utiliza para organizar el desarrollo de NexCode Sales.

## Antes de trabajar
1. Revisar el README y la documentación de `docs/`.
2. Consultar las tareas abiertas en GitHub Issues o en el tablero del equipo.
3. Confirmar con el equipo qué archivo o módulo se va a modificar.
4. No subir contraseñas, claves, tokens ni datos privados.

## Cambios y commits
- Realizar cambios pequeños y relacionados.
- Usar nombres descriptivos para archivos, variables y funciones.
- Escribir mensajes de commit claros, por ejemplo:
  - `docs: actualizar requisitos del sistema`
  - `feat: agregar registro de productos`
  - `fix: corregir validación de ventas`
  - `test: agregar pruebas de inventario`

## Pull requests
1. Explicar qué se cambió y por qué.
2. Indicar cómo se verificó el cambio.
3. Relacionar el Issue correspondiente, si existe.
4. Solicitar revisión de otro integrante antes de integrar cambios importantes.

## Calidad
- No declarar una función como terminada si todavía no está implementada.
- Probar los cambios antes de integrarlos.
- Mantener actualizada la documentación cuando cambie el comportamiento del sistema.
